# Reach: a private instance publishes nothing, a public one announces its channel

> **Status:** extended by [ADR 0013](0013-nsite-hosting.md): public reach through mirrors, public-only URLs, kind 10063 and optional nsite hosting/deletion. Leaves ADR 0008 unchanged: signed-in visitor identity lookup stays mandatory in both reaches.

Owners who run an instance for family, a club or a LAN want it to stay unannounced: no channel profile on the network, videos and comments only under its address. Owners who publish want the opposite, other Nostr apps finding the channel. One switch decides it: **Reach** (Studio: "Privat / Öffentlich").

**`reach = "private" | "public"` in `config.toml`.** Absent means `private`, also for config files from before the field. The studio edits it as `config.reach` (`GET`/`PUT /api/admin/config`) and is told `canBePublic` and `originIsPublic` next to `origin` and `tls`. Public needs a public origin or at least one public mirror relay and one public mirror Blossom server (ADR 0013). Local-ca, `.local`, local names and IP origins are not public; without the required public mirrors the server refuses public in a PUT and when loading the file. Reach applies while running (ADR 0010), no restart.

**Private: the instance publishes nothing.** The server signs no kind 10002 and sends nothing to the indexers; the only outgoing copies go to the `[mirror]` targets the owner typed in (ADR 0009), which the outbox serves in both reaches. The server enforces the read side in the public config: `videoSources` and `interactionRelays` are only the instance relay (`wss://<origin authority>`), so video catalog, creator data and interactions stay on the instance. The stored lists stay as configured and the studio shows them, so switching to public and back loses nothing. Clients obey the lists they get.

**The visitor identity lookup does not depend on reach.** The site is public, and a visitor who signs in must see their own name and avatar even when the instance holds no copy. So in both reaches the site looks the signed-in visitor's kinds 0 and 10002 up exactly as ADR 0008 defines: instance relays, the mandatory public defaults (`wss://purplepag.es`, `wss://nos.lol`, `wss://relay.damus.io`), the configured `profileRelays` and the visitor's NIP-65 write relays. `profileRelays` goes into the public config as stored in both reaches; `profile_relays` stays editable in private reach. A private instance therefore does not promise zero external traffic: the visitor's own key and IP address reach the indexers, as ADR 0008's privacy tradeoff states. The embed and guests make no such lookup.

**Public: the channel is announced.** With the managed key (ADR 0007) the server signs a NIP-65 relay list (kind 10002): the publicly reachable instance first for read/write, then public mirror relays, without duplicates; S2 lists mirrors only (ADR 0013). Like the derived profile and Blossom server list (kind 10063), it is rebuilt at startup and settings changes, replaced only when changed, always strictly newer. The outbox delivers current kinds 0, 10002 and 10063 to `profile_relays` (default `wss://purplepag.es`, `wss://nos.lol`, `wss://relay.damus.io`); with nsite hosting, kind 15128 also goes there. The public config serves public configured video/interaction relays and public mirror relays, excluding unreachable instance endpoints.

**NIP-05 in both reaches.** `GET /.well-known/nostr.json` (with or without `?name=`) answers `{"names":{"_":<hex>},"relays":{<hex>:[...]}}` with `Access-Control-Allow-Origin: *`. The key is the managed key when the server holds one, else the first displayed creator (own identity); without either, or for any name but `_`, the answer is `{"names":{}}`. `relays` is the instance relay in private reach and the public kind 10002 list in public reach. Only a publicly reachable origin contributes `nip05: "_@<origin host>"` to the derived profile; an S2 origin cannot verify a public NIP-05 identity (ADR 0013). In own identity the server signs nothing.

**Privacy tradeoffs.** Public cannot be fully taken back: indexers and their copies keep the profile and relay lists. Switching to private stops new indexer deliveries, with pending indexer jobs waiting until public resumes. No profile or relay-list deletion is attempted. ADR 0013 adds one explicit owner-chosen exception: disabling an nsite can send its NIP-09 manifest deletion and delete its unreferenced ledger blobs with durable retries, even after switching private; copies may remain. In both reaches the indexers see a signed-in visitor's IP address and public key (ADR 0008).

## Considered Options

- **Skip the visitor lookup in private reach (zero external traffic):** rejected; a signed-in visitor would see a blank name and avatar on a site anyone can open, and the lookup reveals only the visitor's own key, from their own browser.
- **Rewrite the stored relay lists when switching to private:** rejected; enforcing them in the public config keeps the owner's lists for the way back.
- **Delete the published profile and relay list when switching back to private:** rejected; deletion is not reliable on the network and would only suggest a revocability that does not exist.
- **A separate sender for the indexers:** rejected; the outbox already has the queue, retries and studio status.
