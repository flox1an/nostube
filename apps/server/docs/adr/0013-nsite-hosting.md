# Site hosting is independent of reach; a managed channel can publish a root nsite

The creator site can be served by the instance or published as a static [NIP-5A nsite](https://github.com/nostr-protocol/nips/blob/master/5A.md). This replaces only the site: relay, Blossom, Studio, APIs, NIP-05 and the instance's embed player remain on the instance. This records #153/#154 and extends ADR 0009 and ADR 0012.

**Site hosting** is `site_hosting = "instance" | "nsite"` in TOML (`siteHosting` in Studio); absent means `instance`. Reach remains the owner's explicit, independent `private`/`public` choice. Only an unlocked managed key and public reach permit nsite publication; own identity never offers it and the server never asks the browser to sign background work. Switching to private restores instance hosting.

**Public reach does not require a public instance origin.** The existing origin check derives whether the instance is public: local-ca, `.local`, local names and IP origins are not public. S1 has a public origin and needs no mirrors. S2 is LAN-only and needs at least one publicly reachable mirror relay and one publicly reachable mirror Blossom server before the owner can select public. Mirrors come only from the owner, with no defaults. Removing the last required public mirror while S2 remains public is refused; the owner must first choose private. Merely adding mirrors never switches reach.

**Published endpoints must be publicly reachable.** In S1 the instance comes first, followed by public mirrors without duplicates; S2 lists public mirrors only. This applies to the channel's kind 10002 relay list, NIP-05 relay hints, kind 10063 Blossom server list, manifest `server` tags, and the nsite's baked relay lists. Public video sources and interaction relays also retain the owner's public configured relays. Private reach keeps the instance relay as its read source. Kind 10063 is derived at startup and config changes in both reaches, signed only with the managed key, and replaced only when its tags change. Kinds 0, 10002 and 10063 go through the outbox to profile relays in public reach; only configured mirror relays receive them in private reach. The nsite manifest also goes to its public delivery relays and profile relays so gateways can discover it.

**Media must exist publicly before its URL is announced.** S1 retains instance URLs. In S2 Studio waits until a mirror has confirmed the hash and size of every output, thumbnail and subtitle before publishing or scheduling the video; the event contains only confirmed public Blossom URLs. Managed profile logo/banner images are stored and mirrored as blobs, then published as confirmed mirror URLs, not unreachable `/branding/` URLs. S2 profiles omit the instance's unreachable NIP-05 name. The branding hashes are reused by the nsite, not uploaded as separate copies.

**The outbox pushes bytes when targets cannot pull.** S1 keeps BUD-04 `PUT /mirror`. S2 streams local storage into `PUT /upload`, authorized with a managed-key BUD-11 upload token. Both paths use the existing durable queue, retries, idempotency and hash/size confirmation; large files are never buffered whole. No managed key retains the existing explicit blob-job failure. The manifest cannot be delivered before its referenced files have confirmed public storage.

**The nsite URL is its baked origin**, distinct from the instance's canonical origin: `https://<npub>.<gateway>` by default, with the gateway chosen in Studio (initial selection `nsite.lol`). An optional bare custom domain replaces it; the owner points a CNAME at `<npub>.<gateway>`. Custom-domain TLS is the gateway's responsibility, not guaranteed by the instance. This is one root site, kind 15128 of the managed channel key, without a `d` tag; no kind 5128 snapshots.

**Published files are only the site.** The embedded root shell and identical `/404.html` SPA fallback bake the public config with the nsite origin, public relay lists, hidden videos, pages, theme and branding. Include site assets, fonts, the standalone embed player and its supporting assets, service worker files, default icons, the baked web manifest, and occupied `/branding/<slot>` paths. Never include `/studio/`. The manifest maps paths to SHA-256 hashes and includes title, description, public Blossom servers and the NIP-5A aggregate: SHA-256 of sorted UTF-8 `<hash> <path>\n` lines. The server keeps a durable ledger of version, hash and uploaded servers.

**Redirect only site routes.** With nsite hosting, GET/HEAD `/`, `/v/…`, `/t/…`, `/search`, `/about`, `/imprint` and `/privacy` return 302 to the same path and query on the nsite URL. WebSocket relay traffic and NIP-11 at `/` take precedence. Blossom, Studio, `/admin`, `/api`, `/.well-known/nostr.json`, `/embed.html` and `/branding/*` remain local.

**Automatic publication follows the file set.** Startup with a new embedded build, applied site/config changes, branding changes and changed public endpoints rebuild after a debounce. Only a changed aggregate publishes another manifest, always newer than the previous one; config revision alone must not change the baked files. Studio exposes aggregate, publication time, pending/failure/delivery status and the gateway cache warning (changes may take an hour). After the new version is delivered, remove superseded ledger blobs from their recorded servers through retried jobs, retaining current files and any blob another stored or scheduled event still references.

**Disabling is not deletion.** Turning nsite off or switching to private asks “Delete the nsite now?”; cancel saves nothing, either answer ends the redirect and stops republication. “Keep” preserves public copies and says so. “Delete” signs a NIP-09 kind 5 with `a=15128:<pubkey>:` and `k=15128`, stores it locally and sends it through the outbox to every historical manifest target. BUD-02 deletes the ledger's unreferenced blobs from each recorded uploaded server, including retryable local cleanup. Explicit deletion intents remain dispatchable after reach or mirror targets change. This owner-chosen exception to ADR 0012's no-deletion policy does not delete profiles/relay lists or promise erasure: gateways, relays and Blossom servers may retain copies.

**Accepted losses.** Generic SEO head only; no prerendered video pages, sitemap or feed snapshots (#160 stays parked). S2 visitor comments/reports go only to public interaction relays; Studio does not see them and local moderation cannot affect foreign copies. Interaction pulling is the separate concept in ADR 0014/#164, not part of nsite publication. No own-identity publishing (#159 remains wontfix).
